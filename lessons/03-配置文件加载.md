# 第 3 课：配置文件加载

> 覆盖源码第 388-519 行。这一课讲清楚：皮肤列表是从哪来的，怎么读配置文件，配置文件不存在时怎么办。

---

## 3.1 配置文件长什么样

先看 `configs/player_models.ini`：

```ini
; T阵营皮肤
[T]
北极战士 models/player/arctic/arctic.mdl
中东游击 models/player/guerilla/guerilla.mdl
精英部队 models/player/leet/leet.mdl
凤凰战士 models/player/terror/terror.mdl

; CT阵营皮肤
[CT]
德国GSG9 models/player/gsg9/gsg9.mdl
法国GIGN models/player/gign/gign.mdl
英国SAS models/player/sas/sas.mdl
美国城市特警 models/player/urban/urban.mdl

; 刀皮肤
[Knife]
默认刀 models/v_knife.mdl
```

规则：
- `[T]`、`[CT]`、`[Knife]` 是**分区**（section），表示下面的皮肤属于哪个类型
- 每行一个皮肤：`显示名称 模型路径`，中间用空格分隔
- `;` 开头的是注释

## 3.2 load_player_models：主函数（第 389-487 行）

### 3.2.1 创建动态数组（第 390-395 行）

```pawn
g_aTModels = ArrayCreate(MAX_MODEL_NAME, 1);
g_aTModelNames = ArrayCreate(MAX_SKIN_NAME, 1);
g_aCTModels = ArrayCreate(MAX_MODEL_NAME, 1);
g_aCTModelNames = ArrayCreate(MAX_SKIN_NAME, 1);
g_aKnifeModels = ArrayCreate(MAX_MODEL_NAME, 1);
g_aKnifeModelNames = ArrayCreate(MAX_SKIN_NAME, 1);
```

`ArrayCreate(大小, 增长量)` 创建动态数组。第一个参数是每个元素占多少字节（这里是字符串最大长度），第二个参数是扩容步长。

> 注意：这里创建了 6 个数组。如果这个函数被调用两次，会重复创建（旧数组泄漏）。好在它只在 `plugin_precache` 里调用一次。

### 3.2.2 拼接配置文件路径（第 397-399 行）

```pawn
new szPath[256];
get_localinfo("amxx_configsdir", szPath, charsmax(szPath));
format(szPath, charsmax(szPath), "%s/mixsystem/player_models.ini", szPath);
```

`get_localinfo` 拿到配置目录（如 `addons/amxmodx/configs`），然后 `format` 拼上 `/mixsystem/player_models.ini`。

> 所以完整路径是 `addons/amxmodx/configs/mixsystem/player_models.ini`。注意：这个路径和 `plugin_init` 里创建的 `mixsystem` 目录是对应的。

### 3.2.3 打开文件 + 防御检查（第 401-406 行）

```pawn
new f = fopen(szPath, "rt");
if (!f) {
    log_amx("[SkinSystem] 普通皮肤配置文件不存在: %s, 使用内置默认模型", szPath);
    load_default_player_models();
    return;
}
```

`fopen(szPath, "rt")` 以文本只读模式打开文件，返回文件句柄 `f`。如果文件不存在，`f` 为 0（假）。

> 这里有一个关键的 `if`：`if (!f)`。它的意思是"如果文件打开失败"。此时调用 `load_default_player_models()` 加载内置默认皮肤（3.3 节），然后 `return` 退出。这是**容错机制**：配置文件丢了，插件也能用默认皮肤跑起来，不会崩溃。

### 3.2.4 声明解析状态（第 408-410 行）

```pawn
new szLine[512];
new bool:bInT = false, bool:bInCT = false, bool:bInKnife = false;
new iLineNum = 0;
```

- `szLine`：每行内容
- `bInT / bInCT / bInKnife`：三个布尔标志，记录"当前正在读哪个分区"
- `iLineNum`：行号（用于调试）

> 这三个布尔变量是解析器的"状态机"。读到 `[T]` 就把 `bInT` 设为 true，读到 `[CT]` 就切换。下面每行数据根据当前状态决定放进哪个数组。

### 3.2.5 逐行读取（第 412-416 行）

```pawn
while (!feof(f)) {
    fgets(f, szLine, charsmax(szLine));
    trim(szLine);
    iLineNum++;
```

`while (!feof(f))` 循环，直到文件结束（`feof` = end of file）。`fgets` 读一行，`trim` 去掉首尾空格。

### 3.2.6 跳过注释和空行（第 418-420 行）

```pawn
if (szLine[0] == ';' || szLine[0] == '/' && szLine[1] == '/' || szLine[0] == EOS) {
    continue;
}
```

这是一个**组合判断**，用 `||`（或）连接三个条件，任何一个成立就跳过这一行：

| 条件 | 含义 |
|------|------|
| `szLine[0] == ';'` | 以分号开头（注释） |
| `szLine[0] == '/' && szLine[1] == '/'` | 以 `//` 开头（注释） |
| `szLine[0] == EOS` | 空行（第一个字符就是字符串结尾） |

> 注意运算符优先级：`&&`（与）比 `||`（或）优先级高，所以 `szLine[0] == '/' && szLine[1] == '/'` 会先结合成一个整体，再和另外两个用 `||` 连接。等价于 `(A) || (B && C) || (D)`。

### 3.2.7 处理分区头（第 422-451 行）

```pawn
if (szLine[0] == '[') {
    new len = strlen(szLine);
    if (szLine[len - 1] == ']') {
        szLine[--len] = EOS;
    }
    if (szLine[0] == '[') {
        copy(szLine, charsmax(szLine), szLine[1]);
    }

    if (equali(szLine, "T") || equali(szLine, "Terrorist") || equali(szLine, "TT")) {
        bInT = true; bInCT = false; bInKnife = false;
    } else if (equali(szLine, "CT") || ...) {
        bInCT = true; bInT = false; bInKnife = false;
    } else if (equali(szLine, "Knife") || equali(szLine, "Knives")) {
        bInKnife = true; bInT = false; bInCT = false;
    } else {
        bInT = false; bInCT = false; bInKnife = false;
    }
    continue;
}
```

这一段处理 `[T]` 这样的分区头：

1. `if (szLine[0] == '[')` —— 判断这一行是不是分区头（以 `[` 开头）
2. `if (szLine[len - 1] == ']')` —— 如果结尾是 `]`，把它替换成 `EOS`（截断字符串）
3. `if (szLine[0] == '[')` —— 把开头的 `[` 去掉（把字符串从第 2 个字符开始复制）
4. 然后比较去掉括号后的内容：
   - 是 `T` / `Terrorist` / `TT` → 进入 T 分区
   - 是 `CT` / `Counter-Terrorist` / `CounterTerrorist` → 进入 CT 分区
   - 是 `Knife` / `Knives` → 进入刀分区
   - 其他 → 三个标志全 false（未知分区，忽略）

> `equali` 是不区分大小写的字符串比较。所以 `[t]`、`[T]`、`[Terrorist]` 都能识别。`else` 分支很关键：遇到未知分区（比如 `[USP]`，本版本不支持）时，把三个标志都设 false，这样下面的数据行就不会被错误地加进任何数组。

> 注意 `continue`：处理完分区头就跳到下一行，不会把 `[T]` 当成皮肤数据。

### 3.2.8 解析皮肤行（第 453-469 行）

```pawn
new szName[MAX_SKIN_NAME];
new szModelPath[MAX_MODEL_NAME];
new iSpacePos = contain(szLine, " ");
if (iSpacePos <= 0) {
    continue;
}

copy(szName, iSpacePos + 1, szLine);
copy(szModelPath, charsmax(szModelPath), szLine[iSpacePos + 1]);
trim(szName);
trim(szModelPath);

if (szName[0] == EOS || szModelPath[0] == EOS) {
    continue;
}
```

这一行是"名称 路径"格式的解析：

1. `contain(szLine, " ")` —— 找到第一个空格的位置
2. `if (iSpacePos <= 0)` —— 如果没有空格（位置 <= 0），跳过这行。这是**防御检查**：防止格式错误的行
3. `copy(szName, iSpacePos + 1, szLine)` —— 复制空格前的部分作为名称
4. `copy(szModelPath, ..., szLine[iSpacePos + 1])` —— 复制空格后的部分作为路径
5. `trim` 去掉两边空格
6. `if (szName[0] == EOS || szModelPath[0] == EOS)` —— 如果名称或路径是空的，跳过

> 注意 `copy(szName, iSpacePos + 1, szLine)` 的第二个参数是"复制多少字符"。`iSpacePos + 1` 是因为 `copy` 的第二个参数是长度（含结尾），而空格在第 `iSpacePos` 位，所以名称长度正好是 `iSpacePos` 个字符 + 结尾 = `iSpacePos + 1`。

### 3.2.9 按分区存入数组（第 471-480 行）

```pawn
if (bInT) {
    ArrayPushString(g_aTModels, szModelPath);
    ArrayPushString(g_aTModelNames, szName);
} else if (bInCT) {
    ArrayPushString(g_aCTModels, szModelPath);
    ArrayPushString(g_aCTModelNames, szName);
} else if (bInKnife) {
    ArrayPushString(g_aKnifeModels, szModelPath);
    ArrayPushString(g_aKnifeModelNames, szName);
}
```

根据当前分区标志，把路径和名称分别压入对应的数组。`ArrayPushString` 就是"往列表末尾加一个字符串"。

> 这里三个 `if / else if` 是互斥的：一个数据行只会属于一个分区。

### 3.2.10 关闭文件 + 日志（第 483-486 行）

```pawn
fclose(f);
log_amx("[SkinSystem] 普通皮肤: T=%d, CT=%d, Knife=%d", ...);
```

读取完毕，关闭文件，打印每种皮肤的数量。

## 3.3 load_default_player_models：内置默认（第 490-519 行）

当配置文件不存在时调用。它直接把 CS1.6 原版模型写死在代码里：

```pawn
stock load_default_player_models() {
    // T阵营默认模型（CS 1.6 原版）
    ArrayPushString(g_aTModels, "models/player/arctic/arctic.mdl");
    ArrayPushString(g_aTModelNames, "默认T");
    ArrayPushString(g_aTModels, "models/player/guerilla/guerilla.mdl");
    ArrayPushString(g_aTModelNames, "中东游击");
    ...
}
```

- T 阵营：北极战士、中东游击、精英部队、凤凰战士
- CT 阵营：默认CT、德国GSG9、法国GIGN、英国SAS、美国城市特警
- 刀：默认刀

> 注意：CT 的"默认CT"和"德国GSG9"用了同一个模型 `gsg9.mdl`，只是名字不同。这是个小瑕疵，不影响功能。

## 3.4 小结

这一课的核心是**解析配置文件**：

```
打开文件 → 逐行读 → 跳过注释/空行 → 识别分区 → 解析"名称 路径" → 存入数组
如果文件不存在 → 用内置默认
```
