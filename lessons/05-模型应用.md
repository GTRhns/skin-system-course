# 第 5 课：模型应用

> 覆盖源码第 242-286 行、第 552-673 行。这一课讲清楚：玩家换皮肤的核心逻辑——身体模型怎么换、刀模型怎么换、换枪时怎么保持。

---

## 5.1 两种模型

CS 里一个角色有两种模型：

| 类型 | 谁看到 | 路径规律 |
|------|--------|---------|
| 身体模型 | 别人看到（第三人称） | `models/player/文件夹/文件夹.mdl` |
| 刀模型（第一人称） | 自己看到 | `models/v_knife.mdl` |
| 刀模型（第三人称） | 别人看到 | `models/p_knife.mdl` |

> 注意：刀模型分"自己看到的"（v_ 开头，view model）和"别人看到的"（p_ 开头，player model）。换刀皮肤时两个都要换。

## 5.2 set_player_knife_view：设置刀模型（第 245-264 行）

```pawn
stock set_player_knife_view(const id, const szPath[]) {
    if (!is_user_alive(id) || !is_user_connected(id)) {
        return;
    }

    // 第一人称视角模型 (自己看到的)
    set_pev(id, pev_viewmodel2, szPath);

    // 生成第三人称模型路径: v_knife → p_knife
    new szPathP[MAX_MODEL_NAME];
    copy(szPathP, charsmax(szPathP), szPath);
    new iPos = containi(szPathP, "v_knife");
    if (iPos >= 0) {
        szPathP[iPos] = 'p';  // v_knife → p_knife
    }

    // 第三人称视角模型 (别人看到的)
    set_pev(id, pev_weaponmodel2, szPathP);
}
```

### 5.2.1 防御检查（第 246-248 行）

```pawn
if (!is_user_alive(id) || !is_user_connected(id)) {
    return;
}
```

这个 `if` 检查两件事：
- `!is_user_alive(id)` —— 玩家是否**没活着**（死了就不用换模型）
- `!is_user_connected(id)` —— 玩家是否**没连接**

两个条件用 `||`（或）连接：**只要有一个不满足就退出**。这是防止对无效玩家操作导致崩溃。

### 5.2.2 设置第一人称模型（第 252 行）

```pawn
set_pev(id, pev_viewmodel2, szPath);
```

`set_pev` 是 fakemeta 的底层函数，设置实体的属性。`pev_viewmodel2` 是"第一人称视角模型"属性（ReGameDLL 字段）。把刀模型路径设置到玩家实体上。

### 5.2.3 生成第三人称路径（第 255-260 行）

```pawn
new szPathP[MAX_MODEL_NAME];
copy(szPathP, charsmax(szPathP), szPath);
new iPos = containi(szPathP, "v_knife");
if (iPos >= 0) {
    szPathP[iPos] = 'p';  // v_knife → p_knife
}
```

1. 复制一份路径到 `szPathP`
2. `containi(szPathP, "v_knife")` —— 在路径里查找 `v_knife` 的位置
3. `if (iPos >= 0)` —— **如果找到了**（位置 >= 0），把那个字符改成 `p`

> 这就是"v_knife → p_knife"的魔法：`models/v_knife.mdl` 变成 `models/p_knife.mdl`。`containi` 的 `i` 表示不区分大小写。

> 为什么用 `if (iPos >= 0)` 判断？因为 `containi` 找不到时返回 -1。如果直接 `szPathP[-1] = 'p'` 会越界写坏内存。这个 `if` 是**安全保护**。

### 5.2.4 设置第三人称模型（第 263 行）

```pawn
set_pev(id, pev_weaponmodel2, szPathP);
```

`pev_weaponmodel2` 是"第三人称武器模型"属性。设置成 `p_knife` 路径。

## 5.3 FM_CurWeapon：换枪时重新应用（第 267-286 行）

```pawn
public FM_CurWeapon(id) {
    if (!is_user_alive(id) || !is_user_connected(id))
        return FMRES_IGNORED;

    new iWeapon = get_msg_arg_int(1);
    if (iWeapon == CSW_KNIFE) {
        if (g_iSelectedKnife[id] >= 0) {
            new iSize = ArraySize(g_aKnifeModels);
            if (g_iSelectedKnife[id] < iSize) {
                new szPath[MAX_MODEL_NAME];
                ArrayGetString(g_aKnifeModels, g_iSelectedKnife[id], szPath, charsmax(szPath));
                set_player_knife_view(id, szPath);
            }
        }
    }

    return FMRES_IGNORED;
}
```

### 5.3.1 为什么需要这个函数

CS 引擎在玩家**切换武器**时会重置武器模型。如果玩家切到刀，刀模型会被重置成默认的 `v_knife.mdl`。所以需要在切刀时**重新应用**玩家选的刀皮肤。

### 5.3.2 逐层 if 分析

```pawn
if (!is_user_alive(id) || !is_user_connected(id))
    return FMRES_IGNORED;
```

第一层：防御检查，无效玩家直接忽略这条消息。

```pawn
new iWeapon = get_msg_arg_int(1);
if (iWeapon == CSW_KNIFE) {
```

第二层：`get_msg_arg_int(1)` 读取消息的第一个参数（武器 ID）。`if (iWeapon == CSW_KNIFE)` —— **只有切到刀时才处理**。切别的武器不管。

```pawn
if (g_iSelectedKnife[id] >= 0) {
```

第三层：`if (g_iSelectedKnife[id] >= 0)` —— 玩家**是否选了刀皮肤**（-1 表示没选）。没选就不用管。

```pawn
new iSize = ArraySize(g_aKnifeModels);
if (g_iSelectedKnife[id] < iSize) {
```

第四层：`if (g_iSelectedKnife[id] < iSize)` —— 选中的索引**是否在数组范围内**。防止存档里的索引超出当前皮肤数量（比如管理员后来删了某个皮肤）导致越界。

```pawn
new szPath[MAX_MODEL_NAME];
ArrayGetString(g_aKnifeModels, g_iSelectedKnife[id], szPath, charsmax(szPath));
set_player_knife_view(id, szPath);
```

取出刀模型路径，重新应用。

> 这一层套一层的 `if`，就是**层层防御**：先查玩家有效，再查是刀，再查选了皮肤，再查索引合法。每一层都防止一种崩溃。

### 5.3.3 返回值

```pawn
return FMRES_IGNORED;
```

`FMRES_IGNORED` 表示"我处理完了，但我不拦截这条消息，让游戏继续正常处理"。因为这里只是补充设置模型，不影响游戏本身的武器切换逻辑。

## 5.4 OnPlayerSpawn：玩家出生时（第 555-559 行）

```pawn
public OnPlayerSpawn(const id) {
    set_task(0.15, "task_apply_model", id);
}
```

这是 `plugin_init` 里 `RegisterHookChain(RG_CBasePlayer_Spawn, "OnPlayerSpawn", true)` 的回调。玩家每次出生时调用。

它不直接应用模型，而是 `set_task(0.15, ...)` **延迟 0.15 秒**再应用。

> 为什么延迟？注释说得很清楚："ReGameDLL post-hook 可能在 deadflag 重置前触发"。也就是说，出生事件触发时，玩家可能还没完全"活过来"，直接应用模型可能失败。延迟 0.15 秒后，玩家肯定活着了。

## 5.5 task_apply_model：延迟后的应用（第 561-566 行）

```pawn
public task_apply_model(const id) {
    if (!is_user_alive(id)) {
        return;
    }
    apply_model(id);
}
```

`set_task` 延迟 0.15 秒后调用这个函数。它先检查 `if (!is_user_alive(id))` —— 如果玩家在这 0.15 秒内死了，就不应用了。

> 这里又是一个 `if` 防御：延迟期间玩家可能死亡，所以要再检查一次。

## 5.6 apply_model：应用模型主函数（第 569-627 行）

```pawn
stock apply_model(const id) {
    if (!is_user_alive(id)) {
        return;
    }

    new TeamName:iTeam = get_member(id, m_iTeam);
    new bool:bModelApplied = false;

    // --- 身体模型 ---
    if (iTeam == TEAM_TERRORIST) {
        if (g_iSelectedT[id] >= 0) {
            new iSize = ArraySize(g_aTModels);
            if (g_iSelectedT[id] < iSize) {
                new szPath[MAX_MODEL_NAME];
                new szFolder[MAX_MODEL_NAME];
                ArrayGetString(g_aTModels, g_iSelectedT[id], szPath, charsmax(szPath));
                extract_folder_from_path(szPath, szFolder, charsmax(szFolder));
                rg_set_user_model(id, szFolder, true);
                bModelApplied = true;
            }
        }
    }
    else if (iTeam == TEAM_CT) {
        // 同理，用 g_iSelectedCT
    }

    // --- 刀模型 ---
    if (g_iSelectedKnife[id] >= 0) {
        new iSize = ArraySize(g_aKnifeModels);
        if (g_iSelectedKnife[id] < iSize) {
            new szPath[MAX_MODEL_NAME];
            ArrayGetString(g_aKnifeModels, g_iSelectedKnife[id], szPath, charsmax(szPath));
            set_player_knife_view(id, szPath);
        }
    }
    ...
}
```

### 5.6.1 第一层防御（第 570-572 行）

```pawn
if (!is_user_alive(id)) {
    return;
}
```

玩家没活着就不应用。

### 5.6.2 获取阵营（第 574 行）

```pawn
new TeamName:iTeam = get_member(id, m_iTeam);
```

`get_member` 是 ReGameDLL 的 API，`m_iTeam` 是玩家的阵营属性。返回 `TEAM_TERRORIST`（土匪）或 `TEAM_CT`（警察）。

### 5.6.3 应用身体模型（第 578-606 行）

```pawn
if (iTeam == TEAM_TERRORIST) {
    if (g_iSelectedT[id] >= 0) {
        new iSize = ArraySize(g_aTModels);
        if (g_iSelectedT[id] < iSize) {
            new szPath[MAX_MODEL_NAME];
            new szFolder[MAX_MODEL_NAME];
            ArrayGetString(g_aTModels, g_iSelectedT[id], szPath, charsmax(szPath));
            extract_folder_from_path(szPath, szFolder, charsmax(szFolder));
            rg_set_user_model(id, szFolder, true);
            bModelApplied = true;
        }
    }
}
```

三层 `if`：
1. `if (iTeam == TEAM_TERRORIST)` —— 是土匪阵营才处理 T 皮肤
2. `if (g_iSelectedT[id] >= 0)` —— 玩家选了 T 皮肤
3. `if (g_iSelectedT[id] < iSize)` —— 索引合法

然后：
- `ArrayGetString` 取出模型路径
- `extract_folder_from_path` 从路径提取文件夹名（5.7 节）
- `rg_set_user_model(id, szFolder, true)` —— **关键函数**，真正设置玩家身体模型。第三个参数 `true` 表示"强制应用"（忽略阵营限制）
- `bModelApplied = true` —— 标记已应用

> 注意：`rg_set_user_model` 需要的是**文件夹名**而不是完整路径。所以要先 `extract_folder_from_path` 提取。

> 如果玩家是土匪但没选 T 皮肤（`g_iSelectedT[id] < 0`），就什么都不做，用 CS 默认模型。这就是注释说的"否则用CS默认模型（不设置）"。

### 5.6.4 应用刀模型（第 609-616 行）

```pawn
if (g_iSelectedKnife[id] >= 0) {
    new iSize = ArraySize(g_aKnifeModels);
    if (g_iSelectedKnife[id] < iSize) {
        new szPath[MAX_MODEL_NAME];
        ArrayGetString(g_aKnifeModels, g_iSelectedKnife[id], szPath, charsmax(szPath));
        set_player_knife_view(id, szPath);
    }
}
```

刀模型不区分阵营，所以没有 `if (iTeam == ...)` 那层，直接检查"选了没 + 索引合法"。

### 5.6.5 调试日志（第 618-626 行）

```pawn
static iDebugTick2 = 0;
iDebugTick2++;
if (iDebugTick2 % 50 == 0) {
    new szName[32];
    get_user_name(id, szName, charsmax(szName));
    server_print("[Skin-DEBUG] apply_model: %s team=%d, ...", ...);
}
```

`static iDebugTick2` 是**静态变量**，函数调用之间保持值不变（不像局部变量每次调用都重置）。每调用一次加 1，`if (iDebugTick2 % 50 == 0)` —— **每 50 次打印一次**调试日志。

> `%` 是取模运算（求余数）。`iDebugTick2 % 50 == 0` 表示"iDebugTick2 是 50 的倍数时"。这样不会每帧都刷屏，只在每 50 次时打印一次。

## 5.7 extract_folder_from_path：提取文件夹名（第 632-673 行）

```pawn
stock extract_folder_from_path(const szPath[], szFolder[], iLen) {
    new iLastSlash = 0;
    new i, len = strlen(szPath);
    for (i = 0; i < len; i++) {
        if (szPath[i] == '/' || szPath[i] == 92) {
            iLastSlash = i;
        }
    }

    if (iLastSlash <= 0) {
        copy(szFolder, iLen, szPath);
        return;
    }

    new szTemp[MAX_MODEL_NAME];
    copy(szTemp, charsmax(szTemp), szPath[iLastSlash + 1]);

    if (contain(szTemp, "v_knife") >= 0 || contain(szTemp, "v_") >= 0) {
        // 刀模型: 文件夹是倒数第二个斜杠后的部分
        ...
    } else {
        // 身体模型: 去掉 .mdl 后缀
        ...
    }
}
```

### 5.7.1 找到最后一个斜杠（第 633-639 行）

```pawn
new iLastSlash = 0;
for (i = 0; i < len; i++) {
    if (szPath[i] == '/' || szPath[i] == 92) {
        iLastSlash = i;
    }
}
```

遍历整个路径，`if (szPath[i] == '/' || szPath[i] == 92)` —— 如果字符是 `/`（ASCII 47）或 `\`（ASCII 92），记录位置。循环结束后 `iLastSlash` 就是**最后一个**斜杠的位置。

> 注意 `92` 是反斜杠 `\` 的 ASCII 码。这样 Windows 风格路径 `models\player\xxx` 也能处理。

### 5.7.2 没有斜杠的情况（第 641-644 行）

```pawn
if (iLastSlash <= 0) {
    copy(szFolder, iLen, szPath);
    return;
}
```

`if (iLastSlash <= 0)` —— 如果路径里没有斜杠（或斜杠在开头），直接复制整个路径作为文件夹名。

### 5.7.3 提取最后一段（第 646-647 行）

```pawn
new szTemp[MAX_MODEL_NAME];
copy(szTemp, charsmax(szTemp), szPath[iLastSlash + 1]);
```

复制最后一个斜杠后面的内容。比如 `models/player/arctic/arctic.mdl` → `arctic.mdl`。

### 5.7.4 判断是刀模型还是身体模型（第 650 行）

```pawn
if (contain(szTemp, "v_knife") >= 0 || contain(szTemp, "v_") >= 0) {
```

`if` 判断最后一段是否包含 `v_knife` 或 `v_`（说明是刀模型）。刀模型的文件夹提取逻辑不同（要往上再取一层），因为刀模型路径是 `models/v_knife.mdl`，文件夹应该是 `models` 而不是 `v_knife`。

### 5.7.5 身体模型：去掉 .mdl（第 665-672 行）

```pawn
} else {
    new iExt = contain(szTemp, ".mdl");
    if (iExt > 0) {
        szTemp[iExt] = EOS;
    }
    copy(szFolder, iLen, szTemp);
}
```

`if (iExt > 0)` —— 如果找到 `.mdl`，把那个位置替换成 `EOS`（截断）。`arctic.mdl` → `arctic`。

> 这就是为什么 `rg_set_user_model` 需要 `arctic` 而不是 `arctic.mdl`。

## 5.8 小结

这一课是皮肤系统的**核心**：

```
玩家出生 → 延迟0.15秒 → apply_model
  ├─ 身体模型：按阵营选 T/CT 皮肤 → 提取文件夹名 → rg_set_user_model
  └─ 刀模型：set_player_knife_view（第一人称+第三人称）
换枪切刀 → FM_CurWeapon → 重新应用刀皮肤
```
