# 第 9 课：存档系统

> 覆盖源码第 1549-1938 行。这一课讲清楚：玩家的皮肤是怎么被记住的——nvault 数据库、JSON 格式、保存与加载。

---

## 9.1 为什么需要存档

玩家选了一个皮肤，如果服务器重启或玩家重进，皮肤就丢了，那体验很差。所以需要把"玩家拥有哪些皮肤 + 当前选了哪个"**持久化**保存下来。

这个插件用了两种方式：
1. **nvault** —— AMXX 内置的键值数据库（主要方式）
2. **文件** —— 一个 `skin_data.txt` 文件（兼容旧版）

## 9.2 存档的标识：get_player_identifier（第 2058-2072 行）

```pawn
stock get_player_identifier(const id, szOut[], iLen) {
    new szAuth[MAX_AUTHID_LENGTH];
    get_user_authid(id, szAuth, charsmax(szAuth));

    // 正版玩家用SteamID
    if (!equal(szAuth, "STEAM_ID_LAN") && !equal(szAuth, "VALVE_ID_LAN")) {
        copy(szOut, iLen, szAuth);
        return;
    }

    // 盗版玩家用IP
    new szIP[MAX_AUTHID_LENGTH];
    get_user_ip(id, szIP, charsmax(szIP), 1);
    copy(szOut, iLen, szIP);
}
```

这个函数决定"用什么东西来识别一个玩家"：
- 正版玩家（有真实 SteamID）→ 用 SteamID
- 盗版玩家（SteamID 是 LAN 占位符）→ 用 IP

> `if (!equal(szAuth, "STEAM_ID_LAN") && !equal(szAuth, "VALVE_ID_LAN"))` —— 注意这里是 `&&`（且）：**两个占位符都不是**才认为是正版。`!equal` 是"不等于"。

> 用 IP 识别盗版玩家有个缺点：IP 会变（换网络、重启路由器）。这是盗版服务器的无奈之选。

### 9.3.2 构建 JSON 数据（第 1566-1605 行）

```pawn
new szData[1024];
new szAuth[MAX_AUTHID_LENGTH], szIP[MAX_AUTHID_LENGTH], szName[32];
get_user_authid(id, szAuth, charsmax(szAuth));
get_user_ip(id, szIP, charsmax(szIP), 1);
get_user_name(id, szName, charsmax(szName));

// 替换名字中的双引号
new szQuote[2] = {34, 0}; replace_all(szName, charsmax(szName), szQuote, "'");

new iLen = 0;
iLen += format(szData[iLen], charsmax(szData) - iLen, "{^"auth^":^"%s^",^"ip^":^"%s^",^"name^":^"%s^",^"t^":[", szAuth, szIP, szName);
```

这里开始构建一个 JSON 字符串。`^"` 在 Pawn 里表示**转义的双引号**（`\"`）。

> `new szQuote[2] = {34, 0}` —— 34 是双引号 `"` 的 ASCII 码。`replace_all(szName, ..., szQuote, "'")` 把玩家名字里的所有双引号替换成单引号。为什么要这样？因为 JSON 里字符串用双引号包裹，如果名字里有双引号，会破坏 JSON 格式。

然后逐个把 T/CT/刀皮肤数组写进去：

```pawn
// T皮肤数组
for (new i = 0; i < g_iOwnedTCount[id]; i++) {
    if (i > 0) {
        iLen += format(szData[iLen], charsmax(szData) - iLen, ",");
    }
    iLen += format(szData[iLen], charsmax(szData) - iLen, "%d", g_iOwnedT[id][i]);
}
iLen += format(szData[iLen], charsmax(szData) - iLen, "],^"ct^":[");
```

> `if (i > 0)` —— 第一个元素前不加逗号，从第二个开始加。这是 JSON 数组的标准写法：`[1,2,3]` 而不是 `[,1,2,3]`。

最终生成的 JSON 类似：

```json
{"auth":"STEAM_0:1:123","ip":"1.2.3.4","name":"玩家名","t":[0,1,2],"ct":[0],"knife":[0]}
```

### 9.4.2 按优先级查找存档（第 1644-1676 行）

```pawn
new bool:bLoaded = false;

// 尝试SteamID
if (!equal(szAuth, "STEAM_ID_LAN") && !equal(szAuth, "VALVE_ID_LAN")) {
    format(szKey, charsmax(szKey), "skinsys_skin_%s", szAuth);
    if (nvault_get(g_iVault, szKey, szData, charsmax(szData))) {
        bLoaded = true;
    }
}

// SteamID没找到，尝试IP
if (!bLoaded) {
    new szIP[MAX_AUTHID_LENGTH];
    get_user_ip(id, szIP, charsmax(szIP), 1);
    format(szKey, charsmax(szKey), "skinsys_skin_%s", szIP);
    if (nvault_get(g_iVault, szKey, szData, charsmax(szData))) {
        bLoaded = true;
    }
}

// IP也没找到，尝试名字
if (!bLoaded) {
    new szName[32];
    get_user_name(id, szName, charsmax(szName));
    format(szKey, charsmax(szKey), "skinsys_skin_%s", szName);
    if (nvault_get(g_iVault, szKey, szData, charsmax(szData))) {
        bLoaded = true;
    }
}
```

这是一个**三级查找**：
1. 先按 SteamID 找
2. `if (!bLoaded)` —— 没找到再按 IP 找
3. `if (!bLoaded)` —— 还没找到再按名字找

> 每个 `if (!bLoaded)` 都是"前一步失败了才继续"。`bLoaded` 是布尔标志，记录"是否已成功加载"。

> 按名字找是个兜底方案，但名字可能重复、可能改名，所以优先级最低。

逐行读取文件，`if (contain(szLine, szAuth) == -1)` —— **如果这一行不包含玩家的 SteamID**，跳过。依次检查 auth、IP、名字都匹配，才解析。

## 9.7 解析 JSON：parse_skin_json（第 1823-1908 行）

### 9.7.1 主函数（第 1823-1844 行）

```pawn
stock parse_skin_json(const id, const szData[]) {
    // 简单JSON解析（不使用JSON库，手动解析）
    // 格式: {"auth":"xxx","ip":"xxx","name":"xxx","t":[0,1,2],"ct":[0,1],"knife":[0]}

    new szTSection[256];
    if (extract_json_array(szData, "t", szTSection, charsmax(szTSection))) {
        parse_skin_array(szTSection, g_iOwnedT[id], g_iOwnedTCount[id]);
    }

    new szCTSection[256];
    if (extract_json_array(szData, "ct", szCTSection, charsmax(szCTSection))) {
        parse_skin_array(szCTSection, g_iOwnedCT[id], g_iOwnedCTCount[id]);
    }

    new szKnifeSection[256];
    if (extract_json_array(szData, "knife", szKnifeSection, charsmax(szKnifeSection))) {
        parse_skin_array(szKnifeSection, g_iOwnedKnife[id], g_iOwnedKnifeCount[id]);
    }
}
```

对 T/CT/刀分别：
1. `extract_json_array` 提取数组部分（如 `0,1,2`）
2. `if (...)` —— **提取成功**才解析
3. `parse_skin_array` 把 `0,1,2` 解析成数字数组

> 注意：这个插件**没有用 JSON 库**，而是手写了一个极简解析器。好处是不依赖额外模块；坏处是只能解析这种固定格式，不能处理复杂 JSON。

### 9.7.2 提取数组：extract_json_array（第 1847-1872 行）

```pawn
stock bool:extract_json_array(const szJson[], const szKey[], szOut[], iOutLen) {
    new szSearch[32];
    formatex(szSearch, charsmax(szSearch), "^"%s^":[", szKey);

    new iPos = contain(szJson, szSearch);
    if (iPos == -1) {
        return false;
    }

    iPos += strlen(szSearch);

    new iEnd = contain(szJson[iPos], "]");
    if (iEnd == -1) {
        return false;
    }

    new iCopyLen = iEnd;
    if (iCopyLen >= iOutLen) {
        iCopyLen = iOutLen - 1;
    }
    copy(szOut, iCopyLen, szJson[iPos]);

    return true;
}
```

1. 构造搜索串 `"key":[`（比如 `"t":[`）
2. `if (iPos == -1)` —— 找不到就返回 false
3. 定位到 `[` 之后
4. `if (iEnd == -1)` —— 找不到 `]` 就返回 false
5. 复制 `[` 和 `]` 之间的内容

> 注意 `if (iCopyLen >= iOutLen)` —— **防止复制长度超过目标缓冲区**，截断到 `iOutLen - 1`。这是防缓冲区溢出。

### 9.7.3 解析数组：parse_skin_array（第 1875-1908 行）

```pawn
stock parse_skin_array(const szArray[], iOut[], &iOutCount) {
    iOutCount = 0;

    new szTemp[256];
    copy(szTemp, charsmax(szTemp), szArray);
    trim(szTemp);

    if (szTemp[0] == EOS) {
        return;
    }

    new iLen = strlen(szTemp);
    new iStart = 0;

    for (new i = 0; i <= iLen && iOutCount < MAX_OWNED_SKINS; i++) {
        if (szTemp[i] == ',' || szTemp[i] == EOS) {
            if (i > iStart) {
                new szNum[16];
                new iNumLen = i - iStart;
                if (iNumLen >= charsmax(szNum)) {
                    iNumLen = charsmax(szNum) - 1;
                }
                copy(szNum, iNumLen, szTemp[iStart]);
                trim(szNum);

                if (szNum[0] != EOS) {
                    iOut[iOutCount] = str_to_num(szNum);
                    iOutCount++;
                }
            }
            iStart = i + 1;
        }
    }
}
```

把 `0,1,2` 这样的字符串拆成数字数组：

1. `for (new i = 0; i <= iLen && iOutCount < MAX_OWNED_SKINS; i++)` —— 遍历每个字符。注意两个条件：`i <= iLen`（包含结尾）**且** `iOutCount < MAX_OWNED_SKINS`（不超过最大数量）
2. `if (szTemp[i] == ',' || szTemp[i] == EOS)` —— **遇到逗号或字符串结尾**，说明一个数字结束了
3. `if (i > iStart)` —— 数字非空（中间有内容）
4. 复制数字、转成整数、存入数组

> 注意 `i <= iLen`：循环到 `i == iLen` 时，`szTemp[i]` 是 `EOS`（结尾），会触发最后一次"数字结束"处理。这是**用结尾字符作为哨兵**的技巧。

## 9.8 确保默认皮肤：ensure_default_skins（第 1911-1938 行）

```pawn
stock ensure_default_skins(const id) {
    // T默认皮肤（索引0）
    if (!has_skin(id, 0, 0)) {
        give_skin(id, 0, 0);
    }
    if (g_iSelectedT[id] < 0) {
        g_iSelectedT[id] = 0;
    }

    // CT默认皮肤（索引0）
    if (!has_skin(id, 1, 0)) {
        give_skin(id, 1, 0);
    }
    if (g_iSelectedCT[id] < 0) {
        g_iSelectedCT[id] = 0;
    }

    // 刀默认皮肤（索引0）
    if (!has_skin(id, 2, 0)) {
        give_skin(id, 2, 0);
    }
    if (g_iSelectedKnife[id] < 0) {
        g_iSelectedKnife[id] = 0;
    }
}
```

对每个类型做两件事：
1. `if (!has_skin(id, 类型, 0))` —— **如果没拥有索引 0 的皮肤**（默认皮肤），就发放
2. `if (g_iSelectedT[id] < 0)` —— **如果没选任何皮肤**，自动选中默认皮肤（索引 0）

> 为什么需要这个？因为新玩家第一次进服务器时，`g_iOwnedTCount` 都是 0，什么都没拥有。如果不给默认皮肤，玩家连第一个皮肤都选不了。这个函数保证"人人都有默认皮肤"。

## 9.9 小结

存档系统的完整流程：

```
保存：构建JSON → nvault_set（皮肤+选择）→ 写文件备份
加载：SteamID → IP → 名字 → 文件 → 解析JSON → 加载选择 → 确保默认皮肤
```
