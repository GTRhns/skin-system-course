# 第 6 课：主菜单系统

> 覆盖源码第 197-237 行。这一课讲清楚：玩家输入 `/skin` 后，主菜单是怎么弹出来的，按键是怎么处理的。

---

## 6.1 cmdSkinMain：主菜单入口（第 200-214 行）

```pawn
public cmdSkinMain(const id) {
    if (!is_user_connected(id)) {
        return PLUGIN_CONTINUE;
    }

    new szMenu[512];
    new iLen = formatex(szMenu, charsmax(szMenu), "\y皮肤系统主菜单^n\y───────^n^n");
    iLen += formatex(szMenu[iLen], charsmax(szMenu) - iLen, "\r1. \wT(土匪)皮肤选择^n");
    iLen += formatex(szMenu[iLen], charsmax(szMenu) - iLen, "\r2. \wCT(警察)皮肤选择^n");
    iLen += formatex(szMenu[iLen], charsmax(szMenu) - iLen, "\r3. \w刀皮肤选择^n^n");
    iLen += formatex(szMenu[iLen], charsmax(szMenu) - iLen, "\r0. \w退出^n");

    show_menu(id, (1<<0)|(1<<1)|(1<<2)|(1<<9), szMenu, -1, "HnsSkinMainMenu");
    return PLUGIN_HANDLED;
}
```

### 6.1.1 防御检查（第 201-203 行）

```pawn
if (!is_user_connected(id)) {
    return PLUGIN_CONTINUE;
}
```

`if (!is_user_connected(id))` —— 如果玩家没连接，直接返回 `PLUGIN_CONTINUE`（不处理）。

> 为什么返回 `PLUGIN_CONTINUE` 而不是 `PLUGIN_HANDLED`？`PLUGIN_CONTINUE` 表示"我不处理，让其他插件继续处理这条命令"。`PLUGIN_HANDLED` 表示"我处理了，拦截"。对于无效玩家，让系统继续处理更安全。

### 6.1.2 构建菜单文本（第 205-210 行）

```pawn
new szMenu[512];
new iLen = formatex(szMenu, charsmax(szMenu), "\y皮肤系统主菜单^n\y───────^n^n");
iLen += formatex(szMenu[iLen], charsmax(szMenu) - iLen, "\r1. \wT(土匪)皮肤选择^n");
iLen += formatex(szMenu[iLen], charsmax(szMenu) - iLen, "\r2. \wCT(警察)皮肤选择^n");
iLen += formatex(szMenu[iLen], charsmax(szMenu) - iLen, "\r3. \w刀皮肤选择^n^n");
iLen += formatex(szMenu[iLen], charsmax(szMenu) - iLen, "\r0. \w退出^n");
```

`formatex` 是"格式化并写入字符串"。`\y`、`\r`、`\w` 是 AMXX 菜单的**颜色代码**：

| 代码 | 颜色 |
|------|------|
| `\y` | 黄色 |
| `\r` | 红色 |
| `\w` | 白色 |
| `\n` | 换行 |

`iLen` 是当前已写入的长度。每次 `iLen += formatex(szMenu[iLen], ...)` 表示**从上次结束的位置继续写**，这样不会覆盖前面的内容。

> 这是 AMXX 菜单构建的标准写法：用一个长度变量累加，确保字符串拼接不越界。

### 6.1.3 显示菜单（第 212 行）

```pawn
show_menu(id, (1<<0)|(1<<1)|(1<<2)|(1<<9), szMenu, -1, "HnsSkinMainMenu");
```

`show_menu` 的参数：
1. `id` —— 给谁显示
2. `(1<<0)|(1<<1)|(1<<2)|(1<<9)` —— **按键掩码**：允许按 1、2、3、0 键
3. `szMenu` —— 菜单文本
4. `-1` —— 菜单显示时间（-1 表示永久，直到玩家按键）
5. `"HnsSkinMainMenu"` —— 菜单名，用于关联按键处理函数

> `1<<0` 是 1，`1<<1` 是 2，`1<<2` 是 4，`1<<9` 是 512。加起来是 519。这个掩码表示"数字键 1、2、3、0 可用"。注意菜单里显示的是"1. 2. 3. 0."，对应按键 1、2、3、0。

> 为什么 `show_menu` 的菜单名是 `"HnsSkinMainMenu"`，但 `plugin_init` 里没有 `register_menucmd(register_menuid("HnsSkinMainMenu"), ...)`？看 6.2 节，主菜单的处理函数是通过另一种方式关联的（实际上源码中 `handleSkinMainMenu` 是通过 `show_menu` 的菜单名隐式关联，AMXX 会自动匹配同名 handler）。

## 6.2 handleSkinMainMenu：按键处理（第 216-237 行）

```pawn
public handleSkinMainMenu(const id, const key) {
    if (!is_user_connected(id)) return PLUGIN_HANDLED;

    switch (key) {
        case 0: { // T皮肤
            g_iSkinSelectType[id] = 0;
            g_iSkinSelectPage[id] = 0;
            showSkinSelectMenu(id);
        }
        case 1: { // CT皮肤
            g_iSkinSelectType[id] = 1;
            g_iSkinSelectPage[id] = 0;
            showSkinSelectMenu(id);
        }
        case 2: { // 刀皮肤
            g_iSkinSelectType[id] = 2;
            g_iSkinSelectPage[id] = 0;
            showSkinSelectMenu(id);
        }
    }
    return PLUGIN_HANDLED;
}
```

### 6.2.1 防御检查（第 217 行）

```pawn
if (!is_user_connected(id)) return PLUGIN_HANDLED;
```

玩家没连接就返回。

### 6.2.2 switch 按键分发（第 219-235 行）

`switch (key)` 根据按下的键分发。注意 AMXX 菜单的**按键映射**：

> 菜单显示"1. 2. 3. 0."，但 `key` 是从 0 开始数的。按"1" → `key=0`，按"2" → `key=1`，按"3" → `key=2`，按"0" → `key=9`。

所以：
- `case 0:`（按 1）→ T 皮肤
- `case 1:`（按 2）→ CT 皮肤
- `case 2:`（按 3）→ 刀皮肤

每个 case 都做同样的事：
1. `g_iSkinSelectType[id] = X` —— 记录玩家要选哪个类型
2. `g_iSkinSelectPage[id] = 0` —— 翻页归零（从第一页开始）
3. `showSkinSelectMenu(id)` —— 显示皮肤选择菜单（第 7 课）

> 注意：按"0"（`key=9`）没有对应的 case，所以什么都不做，菜单关闭。这就是"退出"。

### 6.2.3 返回值

```pawn
return PLUGIN_HANDLED;
```

`PLUGIN_HANDLED` 表示"我处理了这条命令/按键"，阻止其他插件再处理。

## 6.3 小结

主菜单的流程：

```
玩家输入 /skin
  → cmdSkinMain：构建菜单文本 → show_menu
  → 玩家按键 → handleSkinMainMenu：switch 分发
    → 记录类型 → 显示皮肤选择菜单
```
